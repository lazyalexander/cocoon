# Cocoon Benchmark 设计

[English（权威版本）](DESIGN.md) · 简体中文

本文是[基准测试协议](README.zh-CN.md)和[v0.1 验收门槛](../SPECIFICATION.zh-CN.md)
的执行设计，规定后续采集器必须测量什么。现有真实 VM 验收证明一个小项目流程，
尚未提供时延或容量成绩。功能或测量手段缺失应记为 `blocked`，不能记为零时延或通过。

## 1. 运行层级和权限归属

| 层级 | 触发 | 结论 |
| --- | --- | --- |
| 契约检查 | 每个 PR，Linux CI | Rust/Python/解析器检查；不声称 VM 性能。 |
| 原生协议 | 每个 PR，macOS CI | 构建并签名 runner，检查协议，不启动 guest。 |
| 真实 VM 正确性 | 操作员在固定 Mac 上显式运行 | 计时前完成一次管理链路项目/生命周期验收。 |
| 参考性能 | 基础款 M5 / 16 GB 上的候选版本 | 完整矩阵、私有原始证据、脱敏审阅摘要。 |

操作员拥有镜像导入、注册、授权发放、VM 停止和最终回收权限。主 agent 仅凭限权
grant 导入项目、修改 guest、执行命令及导出产物。benchmark 任务不能自行获取生命
周期权限。采集器用 Python；计时点和可信生命周期观测来自 Rust 宿主与已签名 macOS
runner。Python 不在被测 VM 控制平面内。不得降级为本机执行。

## 2. 固定输入和环境

使用同一提交及 `Cargo.lock` 的 release 二进制。记录宿主程序、guest helper、已签名
runner、内核、initrd、基础磁盘和项目 fixture 的摘要；记录机器型号、macOS build、
系统报告的内存、APFS 卷、电源模式、温度状态、可用磁盘、Rust/Xcode 版本和其他宿主
负载。私有清单保存确切路径与操作员信息；公开摘要只包含摘要值和非敏感机器标签。

默认 VM 为 1 vCPU、512 MiB 内存、8 GiB 逻辑稀疏磁盘、离线。项目 fixture 包含固定
版本字节：一个知识文件、一个由 agent 替换的失败脚本、一个检查脚本和确定性构建
产物。正确性预热需导入、修改、检查、构建并逐字节验证产物。容量 fixture 只有在
guest 镜像确实包含固定版本解释器后，才能加入有界 shell/Python 工作。测量前固定
节奏、输入大小和预期摘要。文件传输使用有种子的不可压缩字节，种子留在私有清单。

## 3. 计时及样本记录

使用宿主单调时钟。时延从 API 接受请求开始，包含排队，直到指定可信观测和持久元
数据提交完成。启动就绪还要求通过认证的 guest 命令返回新的宿主挑战。停止以框架
确认 runner 终止为终点；socket 断开、guest 退出或 PID 消失均不合格。导出在宿主
目标文件刷盘和摘要验证后结束。复合操作分别记录克隆、启动、挑战、guest 执行和
刷盘阶段。

每次操作使用不可变 request ID，每次启动记录 attempt/generation。结果为 `passed`、
`failed`、`unknown` 或 `blocked`，并注明原因；未知操作不能换新 ID 重提。原始操作
ID、单调时间戳、阶段耗时、计数器和观测私下保存。`analyze.py` 接受的私有 JSONL
对每个 run/scenario/metric 存一条数字测量；`host` 是完整配置摘要，而不只是机器
型号。缺失功能不写数字样本，在覆盖清单中记为 `blocked`。不同配置不得混算。

## 4. 测量矩阵

| 分组 | 确切负载与结束观测 | 样本及门槛 |
| --- | --- | --- |
| 本地控制 | 注册、grant、状态查询；持久结果。 | 各 100 次；状态 1,000 次。P95 以规范为准。 |
| 磁盘准备 | APFS 独立工作盘克隆和持久发布。 | 100 次；P95 <= 1 秒。完整复制降级单独报告。 |
| 启动 | 已有磁盘、创建加启动、重启、宿主重启后首次启动；新挑战认证返回。除首次启动外，其他三台 VM 持续工作。 | 各 100 次；首次启动涉及五次宿主重启。门槛见规范。 |
| Guest 命令 | 运行中 guest 的 `/bin/true`；另测固定项目的修改/检查/构建/导出流程。 | 各 100 次；空命令 P95 <= 100 ms。项目阶段在规定门槛前只作诊断。 |
| 停止/版本/回收 | 强制停止至框架确认；已停止 VM 回滚、分支及保留产物后的回收。 | 各 100 次；停止 P95 <= 2 秒、每次 <= 5 秒。回收耗时仍需单独采样。 |
| 文件 I/O | 4 KiB 上传加下载并校验；100 MiB 分方向顺序传输并刷盘。 | 往返 100 次；每方向 30 次，P5 >= 100 MiB/s。当前客户端分块限制不能替代 100 MiB 门槛。 |
| 内存/CPU | 预热后的无 VM 基线，再测一台和八台空闲 VM；计入 manager、runner 及可归属 helper。 | 空闲 10 秒后每秒采样，持续 60 秒；manager <= 32 MiB、每 VM 增量 <= 768 MiB、单 VM 空闲 CPU <= 单核 1%。 |
| 容量 | 先四台活跃，再八台常驻、四台活跃；每 VM 一个主 agent，小 agent 共用该 VM 限额，宿主编辑器/浏览器负载可重复。 | 两种配置各两小时；每 10 秒采内存压力/交换并做健康挑战；正确性和停止门槛仍适用。 |
| 恢复/安全 | 各适用持久边界至少注入 10 次故障；测试无效、过期、撤销、跨 VM grant。 | 无重复副作用或越权宿主动作；未知结果隔离。时延百分位不能掩盖失败。 |

`reclaim_cycles.py` 覆盖真实创建/执行/停止/回收循环；其完整 100 轮结果与时延资格
分开报告。强制 NAT、root/non-root、恶意 guest 路径及磁盘写满场景，在对应功能与故障 fixture
具备前也一样。在覆盖清单保留这些行，不得静默省略。

## 5. 采集顺序与结论

1. 核对产物摘要和可用空间，运行协议检查与一次真实 VM 正确性验收；计时前保存私有
   运行清单。
2. 预热宿主和 guest。在四台活跃 VM 下测短控制、guest 和文件场景；生命周期测试
   轮换所用 VM 槽位。保留所有样本。
3. 测一台及八台 VM 的内存/CPU，再执行两种容量配置；通过宿主停止每台 VM 并核对
   框架观测。
4. 在一次性私有状态和有界测试卷执行故障/安全场景；绝不填满开发者系统卷。
5. 使用 `benchmarks/analyze.py` 统计。百分位通过要求完整样本数、零失败和零未知。
   对 F01–F11 及规范全部性能门槛提供覆盖表，标记 `passed`、`failed`、`unknown`
   或 `blocked`，附证据摘要和源码修订号。

CI 只跑确定性检查。真实 VM 计时由操作员发起，不阻塞普通 PR。候选版本只有在参考
M5 配置上全部强制门槛都有真实证据、失败得到解决且脱敏报告经过审阅时才能通过。
原始样本、路径、grant token、镜像和 guest 输出不得提交。
