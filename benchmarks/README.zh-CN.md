# Cocoon 基准测试协议

[English（权威版本）](README.md) · 简体中文

[执行设计](DESIGN.zh-CN.md)将 v0.1 门槛对应到具体负载、样本量、计时边界、证据和
未实现功能的报告方式。

在注明型号的 Apple Silicon 宿主上测量 release 构建，固定 macOS、内核、根镜像、
runner、Rust 工具链和电源模式，并在私有运行清单记录版本与摘要。使用真实 Rust 宿主
服务及框架 runner；契约测试、预检、模拟响应和本机执行降级均不计入成绩。

| 场景 | 测量 | 必要观测 |
| --- | --- | --- |
| 冷创建/启动/停止 | 宿主单调时钟耗时和 p95 | 框架启动/停止证据，VM 无 unknown |
| 热 guest 文件/命令 | 请求响应延迟、吞吐、退出码 | 正确字节和 attempt/generation 关联 |
| 导入/导出 | 4 KiB、1 MiB、16 MiB 的延迟与吞吐 | 摘要、受控宿主目录、基础镜像未变 |
| 内存/磁盘 | 空闲与活跃宿主 RSS、实际/逻辑磁盘 | 1/4/8 常驻及 1/4 活跃，无交换或 OOM |
| 饱和度 | 1/2/4 调用者的工作吞吐和 p95 | 每个 VM 一个主 agent，小 agent 共享限制 |
| 恢复 | 每个持久化意图边界的崩溃/超时/终止 | 不重复命令，未知结果隔离 |
| 安全边界 | 过期/撤销/旧代际/错 VM 授权 | 无越权宿主效果，不泄露私有路径或凭据 |
| 快照 | 暂停/恢复/冷恢复耗时及内存 | RAM nonce、磁盘摘要和原 runner 确认停止 |

先通过正确性预热。每个场景至少收集 100 个独立成功样本以计算时延分布，
p99 至少 300 个；任何失败或未知样本均使该场景不完整，重试使用新 ID。
报告中位数、nearest-rank p95/p99、样本量、失败及未知数。
镜像构建/下载与 VM 生命周期计时分开；不同宿主和镜像配置不得混算，
不能用其他 Mac 的结果宣称 M5/16 GB 达标。

门槛以[验收规范](../SPECIFICATION.zh-CN.md)为准；未规定的指标不编造通过线。
JSONL 每行格式见 [English](README.md)；
`python3 benchmarks/analyze.py private-samples.jsonl` 检查身份并统计，
不采集或伪造样本。原始数据、运行清单、guest 输出与私有路径不入 Git。
发布资格需要真实 macOS VM 证据与人工审阅；CI 只运行确定性检查，不做抖动较大的时延门禁。
